# Anya Storage Plus upgrade progression

**First batch — advanced pickup and advanced compacting.** Both are available in the modules.1 candidate. This document compares the seven working Anya backpack modules at source revision `30f83c2` with the registered upgrades in [Sophisticated Storage](STORAGE_UPGRADE_REFERENCE.md) 1.6.18.2229 and Core 1.5.35.2473, for Minecraft 1.21.1. It is an independent design proposal. A feature marked **Done** exists in the inspected Anya source. **Next** is proposed work, **Optional** is a later choice, and **Blocked** identifies a concrete dependency or an intentionally excluded ability. No new acceptance result or release is implied.

## What to craft first

| Status | Module and recipe | What the player gets |
|---|---|---|
| **Implemented in modules.1** | `anyastorage:advanced_pickup_upgrade`. Shapeless: one `pickup_upgrade`, one amethyst shard, one name tag, one copper ingot. | The carried bag accepts the union of explicit item IDs and explicit item tags. Use the existing pickup filter/input for an item ID or `#namespace:tag`. When both lists are empty, keep the existing matching-stack behavior. Protected inventory slots stay protected. No dropped-item scan. |
| **Implemented in modules.1** | `anyastorage:advanced_compacting_upgrade`. Shapeless: one `compacting_upgrade`, one piston, one comparator, one amethyst shard. | The existing Compact button processes up to **eight identical 9:1 conversions** of one material per click, subject to input and output space. Produced ingots cannot feed a second block recipe in the same click. The existing recipe check, component restrictions and remainder checks still apply. |

Use the existing upgrade slots, settings, input field, and Compact button. An advanced module replaces its basic role in one slot. Both carry and ground installation need the same family checks. Preserve the original exact disc on removal, the bag's existing lists, contents and appearance, and the server's ability to turn the family off. Test both installing at a placed bag and opening the same bag after pickup/restart. The hosted check exercises registry-aware item serialization and the installation and transfer paths. A full-pack restart and player walkthrough remain separate checks.

## What Anya already stores

- **Done — backpack progression.** The physical `anyastorage:backpack` keeps its `BagId`, name, components, container contents, `Tier`, `TierName`, `Capacity`, `UpgradeSlots`, and `InstalledUpgrades` list. Each installed entry keeps its behavior ID and the original disc stack. The five standard tiers provide 27/1, 45/2, 63/3, 81/4 and 108/5 item slots/upgrade sockets respectively. After Starter, the default costs are 8 iron ingots, 8 gold ingots, 8 diamonds and 4 netherite ingots. Optional materials and predecessor costs are server-configurable. Opening old bags respects stored capacities. Placement stores the actual bag on the ground, and eligible direct attachments modify that bag.
- **Done — distinct home storage.** `anyastorage:chest` has 54 slots. `anyastorage:uwu_cube` is a separately crafted 216-slot container. Its existing gated recipe uses the Storage Core, four nether stars and four dragon ingredients selected by server mode. The hub's ore spending expands network range. Neither mechanism installs backpack discs. The pocket has four original 54-slot chests and up to four optional registered chest pads. The Home Void Cube is an entrance. Pocket building, permissions, appearance and tablet access are separate from upgrade sockets.
- **Done — execution and recipes.** The backpack automation pass selects at most one eligible unique carried bag per player per 20 ticks while no container menu is open. A placed bag can accept discs and expose manual controls; dropping it on the ground does not start this carried automation loop. The seven existing disc recipes use four paper, one redstone and four family ingredients listed below. `recipes.upgrades` gates their recipe group, `upgrades.<id>` gates that module's recipe and behavior, and disabling a module keeps installed data. Existing save keys include `PickupFilter`, `SmeltFilter`, `FuelTicks`, `SmeltTicks`, `SmeltRecipe`, `SmeltInput` and `SmeltXP`.
- **Boundary for new hosts.** Anya transactions limit ordinary item stacks to their real maximum, and placed storage presently rejects anonymous sided insertion/extraction. Distinct stack quantities, fluid tanks, and machine automation each need their own implementation. Existing hub routing, protected inventory slots, trip kits, delivery parcels and keepsake displays solve adjacent tasks without creating these hosts.

## Gameplay matrix

Each arrow describes crafting the next module using the previous module plus the listed parts. Listed parts after the first batch are proposals for balancing. Every branch keeps its own behavior, saved state and server gate. Only the two first-batch modules have new registered IDs in this candidate.

| Family and proposed host | Status and current Anya behavior | Regular → advanced proposal |
|---|---|---|
| Pickup · carried bag | **Done** `pickup_upgrade` (hopper). Moves matching items from the player's normal inventory into the bag, skipping protected slots. Empty filter matches existing stacks. **Next** explicit tag matching. | Pickup + amethyst shard, name tag, copper ingot → advanced pickup, as specified above. |
| Compacting · bag, manual | **Done** `compacting_upgrade` (piston). One real 3×3 recipe per click among ten plain material pairs. Requires exact default input components, expected result and no remainders. **Next** batch of one recipe. | Compacting + piston, comparator, amethyst shard → advanced compacting. Reversible shared compression and automatic compacting remain separate capabilities. |
| Feeding · carried bag | **Done** `feeding_upgrade` (golden carrot). Consumes plain food from a small allowlist when its nutrition fits missing hunger. **Next** player-defined timing/food priorities. | Feeding + clock and bowl → advanced feeding with minimum hunger and a priority list restricted to safe foods. |
| Refill · carried bag | **Done** `refill_upgrade` (dropper). Tops up existing matching hotbar stacks with matching components. **Optional** per-slot reserve targets. | Refill + comparator and chiseled bookshelf → advanced refill with selected hotbar slots and minimum bag reserve. |
| Tool resupply · bag, manual | **Done** `resupply_upgrade` (iron pickaxe). Moves one stored tool or sword into an empty selected hotbar slot. **Optional** preferred tool/condition. | Resupply + tripwire hook and grindstone → advanced resupply with tool class and minimum durability. Ordinary tool identity and enchantments travel with the item. |
| Crafting workstation · bag | **Done** `crafting_upgrade` (crafting table). Opens the vanilla portable crafting menu, using the player inventory. **Optional** bag-backed ingredient planning. | Crafting + written recipe template (new blank plan item) and a hopper → advanced crafting with explicit ingredient preview and confirmed transfer from this bag, including remainders. |
| Smelting · carried bag | **Done** `smelting_upgrade` (furnace) already runs automatically for explicitly filtered inputs, with coal/charcoal, real recipe cook times, result/remainder space and fractional XP. **Next** distinguish manual/auto cleanly. | Keep the existing ID and grandfather old automatic behavior. Introduce a manual furnace module for new progression. Manual furnace + clock and powered rail → automatic furnace with input/fuel rules. Both use the saved progress contract below. |
| Smoking · bag | **Next** separate smoker recipe type and manual station. Current smelting does not expose a smoker station. | Manual smoker module made with a smoker → automatic smoker using the manual module, clock and copper grate. Same fuel/remainder safeguards, smoker-specific recipes. |

| Item filter · authorized placed item host | **Next** dedicated input/output filtering. Existing hub exact-item/category routes and bag pickup filters already work within their own paths. | Basic filter uses an explicit item allowlist and one direction. | Magnet · carried bag or explicitly authorized placed host | **Optional** separate world-item collector. ### Capacity and conversion branches

| Family | Status, progression and limits |
|---|---|
| Ordinary slots, sockets, materials | **Done** Starter → Iron → Gold → Diamond → Netherite, purchasing the defined predecessor tier with its configured material. A copied output retains contents, sockets, identity and appearance. **Optional** pack-defined material branches already have configuration support. A proposed in-place chest tier would require the old physical chest and new parts, preserve its exact contents/rights, and use a separate recipe from the existing independently crafted UwU Cube. |
| Stack multipliers and Omega | **Blocked** until there is a durable virtual count per full item identity, compatible extraction, safe breaking and exact UI/network counts. Reference tiers are ×2, ×3, ×4, ×8, ×16, ×32, with Omega as large but finite capacity. For Anya use a dedicated counted host. Basic ×2 → ×3 with copper → ×4 with iron → ×8 with gold → ×16 with diamond → ×32 with netherite, each taking its predecessor. Optional capped endgame tier takes the ×32 module plus a Storage Core. Removing or lowering capacity requires all existing contents to fit. |
| Stack downgrades | **Blocked** on the same counted host. Proposed limiter 1 divides capacity by 8, then limiter 1 + comparator → limiter 2 (/16), then limiter 2 + calibrated sculk sensor → limiter 3 (/32). Show the resulting capacity and deny the operation when occupied counts would exceed it. A limiter is independent of a storage-material tier. |
| Stack conversion tools | **Blocked** on the counted host, actual module tiers and a safe in-place swap. Start with an adjacent-tier converter requiring its module's exact prior tier and the next tier's incremental parts. An advanced direct-jump converter uses the prior converter plus each skipped step's materials. Apply only to its specified installed source, charge once, preserve identity/counts, and cap all routes at their advertised tier. Reference has 15 increasing pairs across its six ordinary stack tiers. |
| Admin Infinity | **Optional, admin-only** after host/storage isolation. Start with an operator-provisioned single-template administrative module. An operator-only upgrade operation consumes that module plus a Storage Core and echo shard for a bounded multi-template version. Enforce authority again on setting templates and generating/withdrawing copies, including through shared networks and automation. Ordinary players cannot generate items. No Survival Infinity item, recipe, transfer loophole or fallback mode. |
| Survival Infinity | **Blocked by design.** Upstream registers this as a separate item with level-zero use privileges. It has no Anya gameplay, crafting, creative-tab or command-generation path planned for Survival. |
| Physical fluid tanks and limited barrels | **Blocked** until dedicated fluid/large-quantity storage schemas exist. A basic sealed tank plus copper/iron lining can become an advanced larger tank without creating fluid. A basic single-material counting chest plus comparator and partitions can become an advanced multi-compartment host without enlarging ordinary ItemStack counts. Freeze extraction and migration if quantities cannot be represented. |

## Save compatibility and acceptance

1. **Old automatic smelters keep working.** Persist an explicit behavior/version when introducing manual crafting. Interpret unmarked installed legacy `smelting` entries as automatic and keep their exact disc, filter, fuel, recipe identity, input components, remaining progress and fractional XP. Existing loose `smelting_upgrade` items must continue to install with their documented legacy behavior. Give the new manual path a distinct ID. A deliberate upgrade conversion can transfer state transactionally without double cooking or losing fuel.
2. **Protect existing packs.** Old schema-2 files were validated against an exact upgrade-key set. The first two advanced discs reuse their existing family switches. Old configurations load with the same seven keys. Treat a disabled basic family as disabled across new tiers unless a documented operator migration explicitly chooses otherwise. Preserve unknown/inactive installed disc data for recovery. Refuse conflicting tier installations and capacity changes that would invalidate contents.
3. **First hosted checks proposed.** Verify both new craft inputs, correct cost, original basic behavior, enabled/disabled gates, and installation/removal through ordinary bag controls and right-click on the placed bag. Test exact/tag union, absent tags after reload, fallback with both lists empty, protected slots and component-correct output. For compacting check 8, fewer than 8, insufficient space, named input, incompatible recipe/remainder and 81 nuggets without recursive block creation. Reopen or restart and compare the saved bag identity, inventory and filters. A published JAR requires a separate build receipt.

Evidence in the inspected Anya tree: `scripts/generate_assets.py` defines primary recipes, `Config.java` and `RecipeCondition.java` control gates, and `Content.java`, `Upgrades.java`, `BagInventory.java`, `BackpackAccess.java`, `BackpackAttachment.java`, `UpgradeRecipe.java`, `Transactions.java`, `StorageEntity.java` and `StoreMenu.java` implement the storage behavior.
