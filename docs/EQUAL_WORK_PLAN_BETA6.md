# Bounded equal-completed-work budget check

This experiment follows SAVE_BUDGET_BETA6.md and BACKPRESSURE_BETA6.md at c72091d83082dc7309fb3de83d761b6fbcf1a3c3. No production integration, replacement playable JAR, operator feature or durability-format change is authorized by this test.

Unfinished performance acceptance: equal completed useful workload including admission/queue waiting and final drain, present journal/reset safeguards included, actual dirty-to-write/flush receipts, complete timing exclusions and residual-stall attribution, retained work and final stop/force-flush obligations. Prior backpressure numbers used about31% fewer completed cycles; later safety tests were not controlled performance comparisons. Hard universal latency bounds and sustained unlimited overload were never established and are not promised here.

One parameter comparison: current32 versus64 maximum serializations per tick, retaining the original256 callback and8ms soft-time allowances. The existing property controls the cap; no budget algorithm changes. All safety switches, current journal/epoch/reset implementations, permission checks, strong tickets and backpressure remain enabled in both arms. Reset protections are present; a healthy workload does not exercise explicit repair/reset, and their execution cost must not be invented.

Two fresh-world/JVM pairs, baseline-first and candidate-first on separate bounded runners. Each first prepares eight rooms, then must finish exactly48 named sample-version updates, six per owner, and all corresponding write plus actual force-flush receipts. It includes admission refusal/retry and full drainage. No timeout may be counted as fewer completed work. Next an identical eight-update dirty tail tests force-save in one pair and normal shutdown in the other, followed by independent raw primary/journal item/identity read-back. Every process remains under360seconds,7000ticks,4GiB sampled RSS,2GiB minimum host availability,92%used heap and15000 destination-cache entries. Real network clients: zero.

The fixture updates names on104 conserved diamonds; this is a serializable useful-storage workload, not a claim of48 inventory transfers. Mutations occur only after authorized opening, matching prior data, prior durability and no quarantine. At most one unconfirmed version exists per monitored sample. Admission intent retries do not replay mutations. At stop the tail's callbacks may not yet all be pending; report observed state rather than calling it a new saturated-backlog test.

Both arms run identical preexisting observers, full tickServer timing, bounded callback-first-observation tracking, journal atomic-write timing, region write/flush timing and identical64MiB bounded JFR recording. Full tick includes fixture and legacy CSV work; its own final metrics gathering/output is outside the bracket. Subspans are inclusive and cannot be added. Worker elapsed times are not main-thread CPU. Queue residence is a lower bound from first observed enqueue presence, with unseen executions separately counted. Receipt confirmation adds unchanged20-tick batch flush and polling. Named receipt registry is bounded and not a universal save journal.

Fixed-work elapsed ends when the48th useful update is durable and runtime queues empty, before independent raw verification. The last full-tick sample does include that verification; report both, do not subtract observer time to fabricate an uninstrumented speedup. Setup, restart and stop/force phases remain separately visible. Source and failed logs must be retained. Compare only within runner and identical phases, not historical different-host maxima.

No promotion unless benefit is consistent for equal completed work and safety checks pass. A mixed or worse result means retain32 and no replacement. This is one bounded comparison, not a performance tuning sweep, full-pack certification, crash atomicity proof or physical storage-failure experiment. Existing no-durable-copy and cross-file non-atomicity limits remain.
